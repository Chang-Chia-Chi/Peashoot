# Coding-agent client compatibility matrix for a local HTTP proxy

Researched 2026-09-12 against primary sources only (official docs, source code, config references, changelogs). Every claim carries a citation; items with no primary source are marked **unverified** and collected at the end.

Purpose: decide which wire APIs a Kotlin/Ktor record/replay + stream-resume proxy must implement, and how each client is pointed at it.

## 2. Per-client notes with citations

### 2.1 Claude Code

**(a) Wire API.** The gateway compatibility guide lists three selectable formats: Anthropic Messages (selected by `ANTHROPIC_BASE_URL`; endpoints `/v1/messages`, `/v1/messages/count_tokens` optional), Amazon Bedrock InvokeModel (`ANTHROPIC_BEDROCK_BASE_URL` + `CLAUDE_CODE_USE_BEDROCK=1`; `/model/{model}/invoke`, `/invoke-with-response-stream`), and Vertex rawPredict (`ANTHROPIC_VERTEX_BASE_URL` + `CLAUDE_CODE_USE_VERTEX=1`). Microsoft Foundry and Claude Platform on AWS also use the Messages format via `ANTHROPIC_FOUNDRY_BASE_URL` / `ANTHROPIC_AWS_BASE_URL`. Inference requests post to `/v1/messages?beta=true` ("Match on the path, not the full URL"). [llm-gateway-protocol](https://code.claude.com/docs/en/llm-gateway-protocol)

**(b) Base URL and auth.**
- `ANTHROPIC_BASE_URL`: "Override the API endpoint to route requests through a proxy or gateway. When set to a non-first-party host, MCP tool search is disabled by default. Set `ENABLE_TOOL_SEARCH=true` if your proxy forwards `tool_reference` blocks." [env-vars](https://code.claude.com/docs/en/env-vars)
- Credential header mapping: "`ANTHROPIC_AUTH_TOKEN` in `Authorization: Bearer`, `ANTHROPIC_API_KEY` in `x-api-key`, and `apiKeyHelper` in both." [llm-gateway-connect](https://code.claude.com/docs/en/llm-gateway-connect)
- Subscription/OAuth: "Setting only [`ANTHROPIC_BASE_URL`], without a gateway credential, doesn't replace the subscription. Requests still route through the gateway, but a saved claude.ai login remains the active credential ... Gateways that pass this traffic on to Anthropic must forward the OAuth capability in `anthropic-beta`." [llm-gateway](https://code.claude.com/docs/en/llm-gateway). Stripping that header "fails those requests with `401`". [llm-gateway-protocol](https://code.claude.com/docs/en/llm-gateway-protocol#request-headers)
- Must forward unchanged: `anthropic-version` and `anthropic-beta` headers ("Forward the header verbatim; don't allowlist individual values"); treat `anthropic-*` headers and body fields as open lists. Body/header pairs (e.g. `context_management`, `output_config`, tool fields `strict`/`defer_loading`) must travel together or you get `400`. `cache_control` markers and block-form `system` must be forwarded unchanged. [llm-gateway-protocol](https://code.claude.com/docs/en/llm-gateway-protocol#feature-pass-through)
- Error bodies must be forwarded unmodified: capability-rejection retry "matches on the upstream's error wording"; a wrapping envelope breaks it unless the message carries a `capability_rejected:` token. [llm-gateway-protocol](https://code.claude.com/docs/en/llm-gateway-protocol#automatic-retry-and-error-forwarding)
- Extra headers: `ANTHROPIC_CUSTOM_HEADERS` (`Name: Value`, newline-separated; v2.1.227+). [env-vars](https://code.claude.com/docs/en/env-vars)
- Best-effort startup traffic: `HEAD /api/hello` warm-up probe (skipped when an HTTP proxy or client cert is configured); `GET /v1/models?limit=1000` discovery only if `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`, 3-second timeout, "any redirect is treated as failure ... even `http` to `https`". Fast-mode check and WebFetch domain-safety check bypass the gateway and call `api.anthropic.com` directly. [llm-gateway-protocol](https://code.claude.com/docs/en/llm-gateway-protocol#optional-endpoints-and-startup-traffic)
- Off-gateway traffic: `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` turns off version checks, telemetry, etc. [llm-gateway-connect](https://code.claude.com/docs/en/llm-gateway-connect)
- System-prompt attribution block (client version + conversation fingerprint) is prepended as the first `system` entry; stable per conversation from v2.1.181; `CLAUDE_CODE_ATTRIBUTION_HEADER=0` omits it. [llm-gateway-protocol](https://code.claude.com/docs/en/llm-gateway-protocol#system-prompt-attribution-block)
- TLS/proxy: `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY` (no SOCKS); `NODE_EXTRA_CA_CERTS`; `CLAUDE_CODE_CERT_STORE`; mTLS via `CLAUDE_CODE_CLIENT_CERT`/`CLIENT_KEY`. [network-config](https://code.claude.com/docs/en/network-config)
- Side effects of a gateway credential: Remote Control and voice dictation unavailable; Remote Control also disabled when `ANTHROPIC_BASE_URL` is non-Anthropic (v2.1.196+). [llm-gateway-connect](https://code.claude.com/docs/en/llm-gateway-connect)

**(c) Streaming, timeouts, retries.**
- "Stream inference responses. Claude Code reads the stream as it arrives, so if your gateway buffers complete responses before relaying them, Claude Code stalls." "On connections through `ANTHROPIC_BASE_URL` ... Claude Code counts every byte your gateway relays, including SSE `ping` events and comment lines, and aborts a stream that goes silent for 300 seconds by default." [llm-gateway-protocol](https://code.claude.com/docs/en/llm-gateway-protocol#streaming)
- Four timers: first-byte deadline (not on `ANTHROPIC_BASE_URL` gateways), event-level watchdog 300 s (every provider), byte-level watchdog 300 s on gateway connections, body idle timeout 5 min on non-direct providers (`API_FORCE_IDLE_TIMEOUT`). `CLAUDE_STREAM_IDLE_TIMEOUT_MS` (min 5 min, byte cap 30 min), `CLAUDE_BYTE_STREAM_IDLE_TIMEOUT_MS`. [network-config](https://code.claude.com/docs/en/network-config#streaming-idle-watchdogs)
- `API_TIMEOUT_MS`: "Timeout for API requests in milliseconds (default: 600000, or 10 minutes)". `CLAUDE_CODE_MAX_RETRIES`: "Override the number of times to retry failed API requests (default: 10). Capped at 15 as of v2.1.186; as of v2.1.199, `CLAUDE_CODE_RETRY_WATCHDOG` raises the default and removes the cap." `CLAUDE_CODE_RETRY_WATCHDOG=1` retries `429`/`529` indefinitely (backoff up to 5 min, honours rate-limit reset), raises other transient retries to 300. [env-vars](https://code.claude.com/docs/en/env-vars)
- Retry semantics: "retries transient failures up to 10 times with exponential backoff"; full budget for server errors, overloaded, timeouts before any output streamed, and dropped connections before any response content; if the connection drops after thinking finished but before text/tool call, re-issues "up to two times in quick succession" then `Connection lost before a response was produced`. [errors](https://code.claude.com/docs/en/errors#automatic-retries)

**(d) Attribution.** Headers: `Authorization`/`x-api-key`, `anthropic-version` (`2023-06-01`), `anthropic-beta`, `x-claude-code-session-id` ("Use it to aggregate all requests from one session without parsing request bodies"), `x-claude-code-agent-id` (subagent requests only), `x-claude-code-parent-agent-id` (nested agents). [llm-gateway-protocol](https://code.claude.com/docs/en/llm-gateway-protocol#request-headers). A model-request `User-Agent` value is **unverified** (docs only document WebFetch's `Claude-User` UA on tools-reference).

**(e) Tool-call visibility.** Native Messages `tools` + `tool_use` blocks; beta tool schema fields `strict` and `defer_loading` and `tool_reference` blocks (MCP tool search) appear in bodies. [llm-gateway-protocol](https://code.claude.com/docs/en/llm-gateway-protocol#feature-pass-through). Built-in tool names/params: `Bash` (`command`, `timeout`), `Read` (`file_path`, `offset`, `limit`), `Edit` (`file_path`, `old_string`, `new_string`, `replace_all`), `Write`, `Glob` (`pattern`, `path`), `Grep` (`pattern`, `path`, `glob`), `WebFetch` (`url`), `WebSearch`, `Agent`, `NotebookEdit`, `PowerShell`, `TaskCreate/Update`, etc. [tools](https://code.claude.com/docs/en/tools)

**(f) Hooks.** 33 events including `PreToolUse`, `PermissionRequest` ("Fires when a tool call needs a permission decision"), `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Notification`, `UserPromptSubmit`, `Stop`, `StopFailure`, `SubagentStart/Stop`, `SessionStart/End`, `PreCompact/PostCompact`, `PreModelSwitch/PostModelSwitch`, `Elicitation`. Input JSON carries `session_id`, `prompt_id`, `transcript_path`, `cwd`, `permission_mode`, `agent_id`; tool events add `tool_name`, `tool_input`, `tool_use_id`. Command hooks (stdin) and HTTP hooks (POST body). [hooks](https://code.claude.com/docs/en/hooks)

Proxy mapping tip: hook `session_id` == header `x-claude-code-session-id`; hook `tool_use_id` == the `tool_use.id` in the streamed response, so hook signals and proxy-observed tool calls join without heuristics (join key documented on both pages above; equality of the two session IDs is **unverified** by an explicit doc sentence).

### 2.2 OpenAI Codex CLI

**(a) Wire API.** Responses API exclusively. Config reference: "`model_providers.<id>.wire_api` (responses) — `responses` is the only supported value, and it is the default when omitted." [config-reference](https://learn.chatgpt.com/docs/config-file/config-reference). Source: `WireApi` enum has only `Responses` (`#[default]`), and `CHAT_WIRE_API_REMOVED_ERROR = "\`wire_api = \"chat\"\` is no longer supported.\nHow to fix: set \`wire_api = \"responses\"\` ... https://github.com/openai/codex/discussions/7782"`. [codex-rs/model-provider-info/src/lib.rs](https://github.com/openai/codex/blob/main/codex-rs/model-provider-info/src/lib.rs). The models page still says "Support for the Chat Completions API is deprecated and will be removed in future releases of Codex" (docs lag the code). [models](https://learn.chatgpt.com/docs/models.md)
- Transport: Responses-over-WebSocket when `supports_websockets` is true — true for the built-in `openai` provider, false for custom and oss providers (`#[serde(default)]`). `responses_websocket_enabled()` = provider supports it and no session fallback; `force_http_fallback` flips a session flag and logs "falling back to HTTP". WS URL is derived from the provider base URL (`websocket_url_for_path`). `OpenAI-Beta: responses_websockets=2026-02-06`. [client.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/client.rs), [responses_websocket.rs](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/endpoint/responses_websocket.rs). Implication: if you override `openai_base_url`, Codex will first attempt a WebSocket upgrade against your proxy; make it fail cleanly (or implement it) so HTTP/SSE fallback kicks in. `features.responses_websockets` flags are `Stage::Removed` (no longer toggles). [features/src/lib.rs](https://github.com/openai/codex/blob/main/codex-rs/features/src/lib.rs)

**(b) Base URL / auth.**
- `openai_base_url`: "Base URL override for the built-in `openai` model provider." `model_providers.<id>.base_url`, `.env_key`, `.http_headers`, `.env_http_headers`, `.query_params`, `.requires_openai_auth` ("uses OpenAI authentication (defaults to false)"), `.experimental_bearer_token`, `.auth` (command-backed bearer: `command`, `args`, `timeout_ms`, `refresh_interval_ms`), `.supports_websockets`, `chatgpt_base_url`, `forced_login_method` (`chatgpt`|`api`). [config-reference](https://learn.chatgpt.com/docs/config-file/config-reference)
- Example (plain HTTP): `[model_providers.proxy] name = "OpenAI using LLM proxy" base_url = "http://proxy.example.com" env_key = "OPENAI_API_KEY"`. Project-local `.codex/config.toml` cannot override `openai_base_url`, `model_providers`, or provider auth (loader denylist). [config-advanced](https://learn.chatgpt.com/docs/config-file/config-advanced.md), [loader/mod.rs](https://github.com/openai/codex/blob/main/codex-rs/config/src/loader/mod.rs)
- `OPENAI_BASE_URL` env var: not listed on the environment-variables page and not read by the current config loader (grep of `codex-rs/config` and `core/src/config` finds only `openai_base_url`); use the config key. [environment-variables](https://learn.chatgpt.com/docs/config-file/environment-variables.md)
- ChatGPT login vs API key: `to_api_provider` picks default base URL `CHATGPT_CODEX_BASE_URL = "https://chatgpt.com/backend-api/codex"` for `AuthMode::Chatgpt` (and token/header modes) and `https://api.openai.com/v1` otherwise; an explicit `base_url` overrides either. ChatGPT auth adds `Authorization: Bearer <token>` and `ChatGPT-Account-ID`. `supports_codex_backend_routes()` is true only for the `openai` provider whose base URL ends with `/backend-api/codex`. [lib.rs](https://github.com/openai/codex/blob/main/codex-rs/model-provider-info/src/lib.rs), [model-provider/src/auth.rs](https://github.com/openai/codex/blob/main/codex-rs/model-provider/src/auth.rs). Docs: "Set `requires_openai_auth = true` to use OpenAI authentication. You can then sign in with ChatGPT or an API key." [auth](https://learn.chatgpt.com/docs/auth.md). Caveat: a ChatGPT-plan token is only valid at the ChatGPT backend; a proxy must forward it there (the proxy cannot swap it for the public API).
- Built-in `openai` provider also sends `http_headers: version=<crate version>` and `env_http_headers: OpenAI-Organization=$OPENAI_ORGANIZATION, OpenAI-Project=$OPENAI_PROJECT`. [lib.rs](https://github.com/openai/codex/blob/main/codex-rs/model-provider-info/src/lib.rs)
- TLS: `CODEX_CA_CERTIFICATE` (PEM bundle), `SSL_CERT_FILE` fallback. [environment-variables](https://learn.chatgpt.com/docs/config-file/environment-variables.md)

**(c) Streaming / timeouts / retries.** `stream_idle_timeout_ms` "Idle timeout for SSE streams in milliseconds (default: 300000)"; `stream_max_retries` "Retry count for SSE streaming interruptions (default: 5)"; `request_max_retries` "Retry count for HTTP requests to the provider (default: 4)". [config-reference](https://learn.chatgpt.com/docs/config-file/config-reference). Source: `DEFAULT_STREAM_IDLE_TIMEOUT_MS = 300_000`, `DEFAULT_STREAM_MAX_RETRIES = 5`, `DEFAULT_REQUEST_MAX_RETRIES = 4`; `ApiRetryConfig { base_delay: 200ms, retry_429: false, retry_5xx: true }`. Stream retries honour server `retry_delay` else backoff. [lib.rs](https://github.com/openai/codex/blob/main/codex-rs/model-provider-info/src/lib.rs), [responses_retry.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/responses_retry.rs)

**(d) Attribution.** `originator` header, default `"codex_cli_rs"` (override `CODEX_INTERNAL_ORIGINATOR_OVERRIDE`); `User-Agent` = `"{originator}/{version} ({os_type} {os_version}; {arch}) {terminal_ua}"`. [default_client.rs](https://github.com/openai/codex/blob/main/codex-rs/login/src/auth/default_client.rs). `build_session_headers` sets `session-id` and `thread-id`. [codex-api/src/requests/headers.rs](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/requests/headers.rs). Also `x-codex-turn-metadata` (JSON incl. `turn_id`), `x-codex-installation-id`, `x-codex-window-id`, `x-codex-parent-thread-id`, `x-openai-subagent` (`review`, `compact`, task name), `x-codex-turn-state` (server-issued sticky-routing token replayed by the client — pass it through both directions), and body `client_metadata`. [client.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/client.rs), [core/tests/responses_headers.rs](https://github.com/openai/codex/blob/main/codex-rs/core/tests/responses_headers.rs)

**(e) Tool-call visibility.** Tools are sent as Responses `tools` (`create_tools_json_for_responses_api`) and calls come back as `function_call` output items / `response.function_call_arguments.delta|done` events, so command/patch arguments are in the stream. [client.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/client.rs), [responses-streaming](https://developers.openai.com/api/docs/api-reference/responses-streaming). The exact built-in tool names (shell / apply_patch) were not verified from docs.

**(f) Hooks / notify.** Events: `SessionStart`, `SessionEnd`, `SubagentStart`, `SubagentStop`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `UserPromptSubmit`, `Stop`, `Interrupt`; files `~/.codex/hooks.json`, `~/.codex/config.toml`, `<repo>/.codex/hooks.json`; common input `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `model`, `turn_id`, `permission_mode`. [hooks](https://learn.chatgpt.com/docs/hooks). `notify` runs a command with JSON `type` (`agent-turn-complete`), `thread-id`, `turn-id`, `cwd`, `input-messages`, `last-assistant-message`. [config-advanced](https://learn.chatgpt.com/docs/config-file/config-advanced.md)

### 2.3 OpenCode

**(a) Wire API.** Provider packages are Vercel AI SDK providers loaded by name: `@ai-sdk/anthropic` (`createAnthropic`), `@ai-sdk/openai` (`createOpenAI`), `@ai-sdk/openai-compatible` (`createOpenAICompatible`), `@ai-sdk/google`, `@ai-sdk/amazon-bedrock`. For the `openai` provider, `getModel` returns `sdk.responses(modelID)` (Responses API); generic path prefers `sdk.responses?.(modelID)` else `sdk.chat?.(modelID)`. [provider.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/provider.ts). Docs: "`@ai-sdk/openai-compatible`: For `/v1/chat/completions` endpoints; `@ai-sdk/openai`: For `/v1/responses` endpoints; `@ai-sdk/anthropic`, `@ai-sdk/google`, `@ai-sdk/amazon-bedrock`: provider-specific". [providers](https://opencode.ai/docs/providers/)

**(b) Base URL.** `provider.<id>.options.baseURL` ("useful for proxy services or custom endpoints"), `options.apiKey` (`{env:VAR}` syntax), `options.headers`, `npm`, `models`; Bedrock `endpoint` is an alias for `baseURL`. [providers](https://opencode.ai/docs/providers/), [config](https://opencode.ai/docs/config/). Anthropic provider default headers: `anthropic-beta: interleaved-thinking-2025-05-14,fine-grained-tool-streaming-2025-05-14`. [provider.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/provider.ts). Anthropic OAuth ("Claude Pro/Max") via `/connect`; docs note Anthropic prohibits using Pro/Max through third-party clients. [providers](https://opencode.ai/docs/providers/). AI SDK Anthropic provider sends `apiKey` as `x-api-key` and `authToken` as `Authorization: Bearer` (`ANTHROPIC_AUTH_TOKEN`). [ai-sdk anthropic](https://ai-sdk.dev/providers/ai-sdk-providers/anthropic)

**(c) Streaming / timeouts / retries.** `timeout` "Request timeout in milliseconds (default: 300000)", `headerTimeout` (300000), `chunkTimeout` "between streamed response chunks (default: 300000)". [config](https://opencode.ai/docs/config/). AI SDK `maxRetries: input.retries ?? 0` (`prompt.ts` passes `retries: 2` on the main path, `0` elsewhere). [llm.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/llm.ts). Session-level `SessionRetry.policy` retries on regexes `/429|500|502|503|504|524/`, rate-limit wording, `overloaded|service unavailable|internal error|...`, honouring `retry-after`. ## 4. (h) Responses API streaming and background/resume

- Streaming event types (SSE, `data:` JSON objects with `type`): `response.created`, `response.queued`, `response.in_progress`, `response.completed`, `response.failed`, `response.incomplete`, `response.output_item.added`, `response.output_item.done`, `response.content_part.added`, `response.content_part.done`, `response.output_text.delta`, `response.output_text.done`, `response.function_call_arguments.delta`, `response.function_call_arguments.done`, `response.reasoning_summary_text.delta`, `error` (plus others). [responses-streaming](https://developers.openai.com/api/docs/api-reference/responses-streaming)
- Background mode: `"background": true` runs asynchronously; poll `GET /v1/responses/{id}` "while the request is in the `queued` or `in_progress` state"; combine `"background": true, "stream": true` to stream immediately; "Each event includes a `sequence_number`"; reconnect with `GET /v1/responses/{id}?stream=true&starting_after=N` where N is the last `sequence_number`; cancel with `POST /v1/responses/{id}/cancel` (idempotent); ZDR projects keep background responses on disk "for roughly 10 minutes". [background](https://developers.openai.com/api/docs/guides/background). `GET /v1/responses/{response_id}` query params: `stream` ("streamed ... using server-sent events"), `starting_after` ("The sequence number of the event after which to start streaming"), `include`, `include_obfuscation`. [responses/get](https://developers.openai.com/api/docs/api-reference/responses/get)
- Implication for stream-resume: only the Responses API has a native resume cursor (`sequence_number` + `starting_after`). Anthropic Messages SSE has no resume; Claude Code re-issues the whole request (up to 10 retries / 2 quick re-issues mid-stream), so the proxy's resume must be implemented by replaying its own buffered SSE for a retried identical request, and it must keep SSE `ping`/comment bytes flowing to satisfy the 300 s byte watchdog. Codex likewise re-issues (`stream_max_retries` 5) and replays `x-codex-turn-state` for sticky routing; whether Codex ever uses `background`/`starting_after` itself is **unverified**.
